# Результат экспериментального переобучения

**Дата: 22 сентября 2026. Статус: НЕ ГОТОВО ДЛЯ РАБОЧЕГО СКАНЕРА.**

Обучающий проект подготовлен, два ограниченных CPU-прогона выполнены,
экспериментальные веса сохранены. Но сеть **не показала достаточного преимущества
над простым совмещением центров облаков**. Называть этот результат правильно
обученным трекером Astra было бы преждевременно.

Исходный файл в `Klischa/astra2` не заменялся. Порог приёмки не снижен ради
успешного отчёта. Реальных данных пользователь не предоставлял; использована
только процедурная синтетика.

## Что исправлено и проверено

1. Восстановлен исходный PointNet в PyTorch. Расхождение с оригинальным ONNX
   на контрольном входе составило примерно **4,8 × 10⁻⁷**.
2. Зафиксированы направление `source → target`, метры и порядок
   `[tx,ty,tz,qx,qy,qz,qw]`. Семантика новой модели теперь записана и в ONNX.
3. Центрирование и общий масштаб находятся внутри графа; исходный перенос
   восстанавливается по формуле `c_target − R*c_source + scale*t_centered`.
4. Введено геометрическое ограничение: одинаковые облака дают единичную позу,
   перестановка входов даёт обратное преобразование. Оно не заменяет обучения.
5. Разделены геометрии train/validation/test. Test не использовался для подбора
   весов, числа шагов или второй архитектурной версии.
6. Проверены загрузка весов, знаковая неоднозначность кватерниона, градиенты,
   восстановление обучения после прерывания и численная эквивалентность экспорта.

## Обучение

| Прогон | Шагов выполнено | Выбранный шаг | Время CPU |
|---|---:|---:|---:|
| Исходная схема + правильная нормализация | 1200 | 200 | ≈125 с |
| Двунаправленная голова с обратимостью | 1200 | 600 | ≈131 с |

Каждый прогон: batch 8, 256 точек на облако, один вычислительный поток.
Стартовые веса энкодера взяты из исходного ONNX; регрессионная голова
переинициализирована, поскольку её исходный обучающий контракт неизвестен.
Обучались и энкодер, и голова. Во второй версии общая голова вычисляется в двух
направлениях без увеличения количества параметров: **1 325 319**.

Checkpoint выбирался по минимуму validation loss, а не по test.
Validation: 96 пар, отдельное пространство из 24 сцен. Обучающее пространство:
128 процедурных сцен. Конфигурации, логи и манифесты сохранены в репозитории.

## Независимый синтетический тест

192 пары: по 64 для каждого режима. В тесте использованы **26 уникальных сцен**
из отдельного пространства в 32 сцены, плюс 64 проверки одинаковых облаков.
Режимы: точное полное перекрытие; независимая выборка с шумом; приближённая
частичная видимость с шумом и выбросами. Облака состоят из 256 точек.

Повороты — до 12° вокруг случайной оси, перенос — до ±25 мм по каждой оси,
дистанция до синтетического объекта — 0,45–0,9 м. Gaussian-шум — σ=0,7 мм;
в частичном режиме около 1% точек заменены выбросами внутри bounding box.
Это не калиброванная модель шума Astra и не полноценный RGB-D рендерер.

| Метод | Средняя ошибка поворота | Средняя ошибка переноса | Доля пар <2° и <10 мм |
|---|---:|---:|---:|
| Совмещение центров, без нейросети | 5,487° | 52,11 мм | 9,38% |
| Переобученная сеть | 5,468° | 50,82 мм | 8,85% |
| Центры + ICP | 1,193° | 10,58 мм | 55,21% |
| Сеть + ICP | 1,135° | 10,34 мм | 58,33% |

Оба варианта ICP используют одни и те же настройки. Основное улучшение даёт
геометрическое уточнение, а не нейросеть. Небольшую разницу между вариантами
с ICP нельзя переносить на реальные сканы или считать доказанным преимуществом.
У варианта «сеть + ICP» 95-й перцентиль ошибки переноса даже хуже:
33,62 мм против 31,33 мм у «центры + ICP».

### По режимам: средняя ошибка «поворот / перенос»

| Режим | Только сеть | Центры + ICP | Сеть + ICP |
|---|---:|---:|---:|
| Полное перекрытие, одинаковый набор точек | 5,439° / 50,36 мм | ≈0° / ≈0 мм | ≈0° / ≈0 мм |
| Независимая выборка, шум | 5,450° / 50,82 мм | 1,782° / 15,60 мм | 1,697° / 15,29 мм |
| Частичная видимость, шум и выбросы | 5,515° / 51,27 мм | 1,798° / 16,14 мм | 1,708° / 15,72 мм |

На одинаковых облаках средняя ошибка новой версии составила около
**0,0000017°** и **0,000029 мм**, то есть практически машинную погрешность.
Это гарантируется устройством двунаправленной головы и **не доказывает**
способность сети оценивать неизвестный поворот.

Оригинальный ONNX также измерен при интерпретации **как в текущем C++-коде**:
174,29° и 2074,92 мм в среднем. Это диагностический результат несовместимости
или плохих предсказаний в данном режиме, а не честная оценка его неизвестного
обучающего контракта. Мы не используем эту слабую базу как критерий успеха.

## Вывод и следующий шаг

Техническая основа для корректного обучения готова, но **готовой замены модели
для Astra пока нет**. Для следующего этапа нужны записанные последовательности
с надёжными позами и реальная отложенная проверка. Затем следует проверить,
достаточна ли глобальная PointNet-регрессия или нужен метод с явными
соответствиями точек. Просто увеличить число эпох и назвать результат готовым —
необоснованно.

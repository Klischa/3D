# Сбор реальных записей Astra с эталонными позами (gt_collector)

`gt_collector` — автономный модуль для записи RGB-D с Astra и **надёжными
GT-позами камеры** в каждом кадре. Отдельный процесс, своё подключение к
камере, свой формат данных; код astra2 не изменяется и не подключается.

## Принцип

* **Мир = координаты дошки с AprilTag.** Дошка жёсткая и статичная во время
  сессии; её система координат (центр, X вправо, Y вниз, Z из печати) —
  мировая. Каждый кадр независим: нет межкадровой карты маркеров,
  инициализации и соответствий.
* **GT считается только по RGB + дошке.** `depth` к позам не прикладывается,
  поэтому ошибки depth-сенсора не попадают в метки. Depth записывается
  как данные (облак в кадре камеры), а позы — отдельно.
* **Поза**: детекция AprilTag (OpenCV, `DICT_APRILTAG_25H9`,
  `CORNER_REFINE_SUBPIX`) → глобальный `solvePnP` по всем 4N углам
  маркеров (SQPNP, фолбэк ITERATIVE) → 4×4 `T_board_from_cam`.
  Качество кадра: пер-маркерные репроекционные резидуалы (мм) + разброс
  нормалей (плоскость дошки).
* **Пары для модели**: `T_target_from_source = inv(T_target) @ T_source`,
  source = текущий кадр, target = предыдущий — контракт
  `pose_regressor` (метры, кватернион x,y,z,w).

## Установка (машина с камерой)

```bash
# Python 3.10+
pip install numpy scipy
pip install "opencv-python-headless>=4.10,<5"
pip install --no-deps pyorbbecsdk2   # import-имя: pyorbbecsdk
# драйвер: установленный Orbbec SDK (USB-драйвер Astra) — обязателен
```

Проверка:

```bash
python -m gt_collector devices        # Astra видна?
python -m gt_collector selftest       # пайплайн на синтетике (камера не нужна)
```

> Известный баг окружения: в opencv-python-headless 4.10–4.14 + numpy 2.x
> отдельные вызовы `detectMarkers`/`solvePnP` на кадрах, содержащих
> кандидатов, могут бросать `TypeError: return arrays must be of ArrayType`
> (баг привязки Python, зависит от состояния процесса). Обход вшит в
> `detectors.py` (пересоздание детектора, повтор на BGR-круге, фолбэк
> SQPNP→ITERATIVE) и учтён в статистике (`detector_open_cv_errors` в
> manifest). Если такие ошибки массовые — попробуйте numpy 2.2.x.

## Подготовить дошку

```bash
python -m gt_collector print-board --board a4 --png board.png --svg board.svg
```

* `a4` — 12 тэгов 50 мм на листе 260×200 мм (базовый). Печатать **в
  масштабе 1:1** (проверить линейкой/экраном).
* Жёсткая основа (картон/ПВХ), матовая печать, без бликов.
* Дошка должна быть **в кадре у большинства позиций оператора** и
  статична во время сессии.

Проверка печати (фото с телефона/Astra на 0,5–1,5 м):

```bash
python -m gt_collector check-board photo.jpg --board a4
# → "ok": true, 12 тэгов, размер ~20–50 px (зависит от расстояния)
```

## Протокол сессии

1. Закрыть astra2 (камера — эксклюзивное устройство).
2. Поставить/приклеить дошку в сцене, убедиться, что оператору удобно
   держать камеру на 0,6–1,5 м от неё по всей области интереса.
3. Записать:

   ```bash
   python -m gt_collector collect --out session_001 \
       --duration 90 --fps 30 --board a4 \
       --scene "kitchen" --operator "KL"
   ```

   Флаги: `--min-tags 5` (минимум видимых тэгов), `--max-residual-mm 20`
   (качество подгонки), `--min-points 20000` (плотность облака).

   **Размер данных.** Каждое сохранённое облако 720p ≈ 8–9 МБ (914k точек ×
   9 байт), кадр ≈ 0.15 МБ. По умолчанию (`--save-every 1`) это ~2.5 ГБ/мин —
   90-секундная сессия ≈ 4 ГБ. Обычно достаточно `--save-every 10`
   (~250 МБ/мин): пары поз берутся из poses.csv на каждый кадр и не зависят
   от частоты сохранения облаков.

### Движение оператора

* Шаг между кадрами ≤ ~10 см / ~10° (жёсткий порог 0,2 м / 20° помечает
  кадр `fast`). 30 fps → скорость ≤ ~60 см/с.
* Плавно, без рывков; дошка не двигается и не трясётся.
* Освещение стабильное, без прямых бликов на дошке.

### Типы сессий (покрывают разные режимы модели)

| Тип | Что даёт | Как |
|---|---|---|
| **Статика** (30–60 с, рука неподвижна) | noise floor GT (разброс поз = нижняя граница ошибки меток) | сессия без движения |
| **Орбита** (обход сцены 0,8–1,5 м) | позы с разным углом на дошку, покрытие | медленный обход сцены, дошка всегда в кадре |
| **Развороты/перемещения по комнате** | большие относительные шаги до порога | обычные обходы сцены |

Рекомендация: 20–40 сессий × 60–120 с, минимум 1 статичная на объект.

## Формат сессии

```
session_001/
  manifest.json    # конфиг, устройство, калибровка, сводка флагов
  poses.csv        # GT-поза КАЖДОГО кадра: 4×4 (т/кватернион), резидуалы, флаги
  report.json      # метрики: valid ratio, резидуалы, noise floor, шаги
  pairs.csv        # пары (source=new, target=old) + T_rel 4×4
  frames/
    0000005.jpg    # RGB
    0000005.cloud  # облак в системе камеры (ACGD v2: xyz int16 мм + rgb)
```

Флаги кадра: `no_board` (<5 тэгов), `poor_fit` (резидуал >20 мм),
`thin` (<20k точек), `fast` (шаг >0,2 м/20°), `stale` (разрыв >80 мс).
Годный кадр = без флагов.

### Калибровка

Заводская калибровка Astra (`Pipeline.get_camera_param()`: K + дисторсии
color/depth, depth→color extrinsic, baseline) читается автоматически и
фиксируется в manifest (`calibration_source: "device factory"`). RGB
унаряживается по этим дисторсиям **перед детекцией**. Своя калибровка
не требуется; при желании — `python -m gt_collector save-calibration
--out calibration.json` (справочно).

## Отчёт и контроль качества

```bash
python -m gt_collector report session_001
python -m gt_collector stats session_001
python -m gt_collector pairs session_001
```

Критерии приёмки сессии:

* `valid_ratio > 0.95` (иначе — плохое освещение/дошка слишком далеко);
* `residual_mm p95 < 10`;
* `noise_floor` (из статичной сессии): `translation_p95_mm < 5`,
  `rotation_p95_deg < 1` — это нижняя граница ошибки GT; если хуже —
  проверить твёрдость дошки, освещение, размер тэгов на экране (25+ px);
* `pairs_summary.json`: средний шаг ~3–10 см, p95 < 15 см.

## Синтетический бэкенд (без камеры)

`python -m gt_collector collect --backend fake ...` и `selftest` работают
на рендерере Astra-подобной камеры (1280×720, K=620, шум+JPEG,
аналитическая глубина, scripted-детекция из GT). Это детерминированный
прогон всего пайплана для CI и отладки; на фейке **не** оценивается
реальная точность детекции (она проверяется `check-board` на реальной
фотографии дошки).

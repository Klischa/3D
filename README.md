# Обучение регрессора позы для Astra

**Статус: эксперимент на синтетике, НЕ готовая модель для камеры.** Два коротких
CPU-прогона выполнены; существенного преимущества нейросети над совмещением центров
не получено. Порог качества **не пройден**. Подробности: [отчёт](reports/RESULTS.md).
Исходный `Klischa/astra2` не изменён.

## Что здесь есть

- Восстановленная из ONNX архитектура PointNet: `3→64→128→1024`, общий энкодер,
  голова `2048→512→256→7` — **1 325 319 параметров**.
- Загрузка исходных весов с проверкой SHA256. Численная эквивалентность
  восстановленного PyTorch и исходного ONNX проверяется тестом.
- Переобучение всего энкодера; голова инициализируется заново, поскольку смысл
  семи исходных каналов не подтверждён кодом обучения.
- Явный контракт позы, восстановление центров и масштаба, единичный кватернион.
- Вариант с общей головой в двух направлениях: одинаковые облака дают `I`,
  перестановка входов даёт обратное преобразование. Новых параметров не добавлено.
- Процедурные пары с точными метками `R,t`, шумом и приближённой частичной видимостью.
  **Это не сканы Astra и не физически точный симулятор её глубины.**
- Разделение train/validation/test по геометрии сцен, не по кадрам одной сцены.
- Сравнение с centroid-базой, centroid+ICP и neural+ICP; автоматические пороги качества.
- Воспроизводимый запуск, безопасная загрузка checkpoint (`weights_only=True`),
  восстановление optimizer/scheduler/RNG при продолжении, экспорт ONNX и проверка его численной эквивалентности.

## Результат текущего эксперимента

На 192 синтетических парах, **256 точек в каждом облаке**:

| Метод | Средняя ошибка поворота | Средняя ошибка переноса |
|---|---:|---:|
| Совмещение центров, без сети | 5,487° | 52,11 мм |
| Переобученная сеть | 5,468° | 50,82 мм |
| Центры + ICP | 1,193° | 10,58 мм |
| Сеть + ICP | 1,135° | 10,34 мм |

Разница между сетью и простой базой слишком мала. **Это не успешное обучение
рабочего трекера.** Отдельная проверка 64 одинаковых облаков пройдена;
это следствие геометрического ограничения архитектуры, а не доказательство
того, что сеть научилась оценивать произвольные движения.

Артефакт для исследования: [`artifacts/pose_regressor.experimental.onnx`](artifacts/pose_regressor.experimental.onnx).
[Описание модели](artifacts/MODEL_CARD.md), [сырые метрики](reports/cpu_synthetic_symmetric_v1.test.json).

## Установка

Проверено на Python 3.11, PyTorch 2.5.1, CPU. Для воспроизведения версий см.
[`requirements-repro.txt`](requirements-repro.txt). GPU-путь в этой сессии не проверялся.

```bash
python -m venv .venv
source .venv/bin/activate             # Windows: .venv\Scripts\activate
python -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements-repro.txt
python -m pip install --no-deps -e .
```

Если официальный CPU-индекс недоступен, обычный `pip install torch==2.5.1`
также работает на CPU, но Linux-сборка из PyPI скачивает большие CUDA-зависимости.
В текущей среде использован именно этот вариант; `torch.cuda.is_available()` вернул `False`.

## Воспроизведение

Все команды выполняются из корня репозитория. Исходный ONNX закреплён за
неизменяемым коммитом и SHA256, а не за текущим содержимым ветки GitHub.
Загрузчик сначала использует HTTPS, а при его недоступности — уже настроенный
GitHub CLI (`gh api`) с закреплённым Git blob. Проверка SHA256 обязательна в обоих
случаях; TLS-проверки не отключаются, секреты в проект не записываются.

```bash
python -m pose_training.fetch_base
python -m pytest

# Три шага: только проверка запуска, НЕ обучение качественной модели.
OPENBLAS_NUM_THREADS=1 python -m pose_training.train \
  --config configs/smoke.json \
  --base-onnx weights/original_pose_regressor.onnx --out runs/smoke-new

# Основной ограниченный CPU-эксперимент: 1200 шагов, batch 8, 256 точек.
OPENBLAS_NUM_THREADS=1 python -m pose_training.train \
  --config configs/cpu_synthetic_symmetric.json \
  --base-onnx weights/original_pose_regressor.onnx --out runs/my-experiment

# Настраивайте только по validation. Test запускайте после выбора модели.
python -m pose_training.evaluate \
  --checkpoint runs/my-experiment/best.pt \
  --original-onnx weights/original_pose_regressor.onnx \
  --split test --pairs-per-mode 64 --out runs/my-experiment/test.json

python -m pose_training.export \
  --checkpoint runs/my-experiment/best.pt \
  --evaluation runs/my-experiment/test.json \
  --out runs/my-experiment/pose_regressor.experimental.onnx
```

В PowerShell переменные окружения задаются, например, через `$env:OPENBLAS_NUM_THREADS="1"`.
Первая конфигурация без двунаправленного ограничения сохранена в
`configs/cpu_synthetic.json`; это контрольный неудачный прогон, не рекомендуемая модель.

### Продолжение прерванного запуска

```bash
python -m pose_training.train --config configs/cpu_synthetic_symmetric.json \
  --out runs/my-experiment --resume runs/my-experiment/last.pt
```

Конфигурация должна совпадать полностью, в том числе число шагов scheduler.
Не используйте эту команду для изменения эксперимента или увеличения уже
завершённого расписания обучения. Точное продолжение проверяется автоматическим тестом.
Численная идентичность между разными версиями библиотек/устройствами не обещается.

## Контракт новой модели — важное отличие от старой

```text
source: float32 [B,3,Ns] — НЕ центрированные XYZ в метрах
 target: float32 [B,3,Nt] — НЕ центрированные XYZ в метрах
pose:   float32 [B,7] = [tx,ty,tz,qx,qy,qz,qw]

p_target = R(qxyzw) @ p_source + t
```

Внутри модели находятся центрирование, общий RMS-масштаб и обратная компенсация:

```text
t_original = center_target − R @ center_source + scale * t_centered
```

Нельзя отдельно центрировать или независимо масштабировать облака перед вызовом!
Модель не выдаёт уверенность и не должна сама решать, принимать ли позу.
[Порядок интеграции в astra2](docs/ASTRA2_INTEGRATION.md) — **только после валидации**.

## Сбор реальных данных: `gt_collector`

Автономный модуль для записи Astra с **надёжными GT-позами в каждом кадре**
(пункт 1 «следующего этапа»). Отдельный процесс и своё подключение к камере
через Orbbec SDK; код astra2 не изменяется.

* **Мир = жёсткая дошка с AprilTag** (12 тэгов 50 мм на A4,
  `DICT_APRILTAG_25H9`). Поза камеры в каждом кадре — глобальный `solvePnP`
  по всем углам тэгов, **только по RGB**: depth к меткам не прикладывается.
* Кадры помечаются флагами качества (`no_board`, `poor_fit`, `thin`,
  `fast`, `stale`); из годных кадров извлекаются пары
  `T_target_from_source` в контракте модели (source = новый кадр).
* Формат сессии: `poses.csv` (4×4 + резидуалы на кадр), облака `ACGD`
  (xyz int16 мм + RGB, 9 байт/точку), JPEG, `manifest.json`, `report.json`
  (noise floor из статичных сессий, распределения резидуалов и шагов).
* Без камеры модуль проверяется синтетическим бэкендом (рендер RGB+depth
  из GT-позы): `python -m gt_collector selftest` — точность пайплайна
  0,1°/0,8 мм (mean), noise floor 1,9 мм/0,65° (p95).
* CLI: `collect | selftest | report | pairs | stats | save-calibration |
  check-board | print-board | devices`. Протокол съёмки, критерии приёмки
  сессий и установка — [docs/DATA_COLLECTION.md](docs/DATA_COLLECTION.md).

## Что нужно для следующего этапа

1. Реальные записанные последовательности Astra с эталонными позами, либо
   независимо проверенная разметка. Результат ICP без проверки не является ground truth.
   Инструмент для сбора — `gt_collector` (выше).
2. Зафиксировать рабочий диапазон движения, дистанции, перекрытие, шум глубины и частоту кадров.
3. Разделить реальные объекты/сцены и сеансы на обучение, validation и закрытый test.
4. Сравнить не только со старым ONNX, но и с геометрическим трекингом по ошибкам,
   доле срывов, дрейфу на последовательностях и времени обработки.
5. После этого решать, достаточно ли PointNet-регрессии или нужна архитектура
   с явными соответствиями точек. Больше эпох само по себе не гарантирует решения.

Данные, исходные веса и checkpoint хранятся вне Git (`data/`, `weights/`, `runs/`).
В Git включён только небольшой экспериментальный ONNX и отчёты.
Атрибуция и ограничения лицензии производных весов: [THIRD_PARTY.md](THIRD_PARTY.md).
